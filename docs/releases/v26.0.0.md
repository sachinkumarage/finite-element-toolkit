# v26.0.0 — Advanced Solver Infrastructure

This release adds sparse matrix storage and solving as a parallel, opt-in
path alongside the toolkit's existing dense linear algebra, plus a formal
solver abstraction with structured convergence and performance diagnostics.
It changes no existing element, material, or dense-solve behavior — every
prior version's test suite passes unchanged.

## Added

- **Sparse global assembly** (`femtoolkit.analysis.sparse_assembly`) —
  direct-to-CSR stiffness and mass assembly via SciPy COO triplet
  accumulation (`assemble_global_stiffness_sparse`,
  `assemble_global_mass_sparse`), avoiding any dense-then-convert
  intermediate step. Verified mathematically identical to the existing
  dense assembler for real Q4/CST element contributions, including
  shared-DOF summation.
- **Sparse multi-point constraints** — `apply_multi_point_constraints_sparse`
  in `femtoolkit.analysis.multi_point_constraint`, the sparse counterpart
  of the existing dense penalty-method MPC, verified to match it exactly.
- **A new `femtoolkit.solvers` package** — a `LinearSolver` abstraction
  (`base.py`) built on the unchanged `LinearSystem` container, with three
  implementations: `DenseDirectSolver`, `SparseDirectSolver`
  (SciPy `spsolve`), and `ConjugateGradientSolver` (an iterative solver for
  symmetric positive-definite sparse systems). A `create_solver(matrix_type,
  solver_type, ...)` factory selects among them and rejects the
  architecturally-unsupported dense + conjugate-gradient combination.
- **Structured solver diagnostics** — every solve returns a `SolverResult`
  (solution, `converged`, `iterations`, `residual_norm`,
  `relative_residual`, `solve_time`, `solver_name`, `diagnostics`) instead
  of a bare array, computed via one shared `residual_norms` helper so
  direct and iterative solvers report convergence identically.
- **A latent numerical-robustness fix** — `check_direct_solve_residual`
  detects a direct solve on a matrix that is singular in exact arithmetic
  but has a tiny nonzero floating-point pivot (an under-constrained
  rigid-body mechanism), which `numpy.linalg.solve` and
  `scipy.sparse.linalg.spsolve` do not reliably flag on their own, and
  raises the existing `SingularSystemError` instead of returning
  huge-magnitude, physically meaningless displacements silently.
- **Zero-regression integration** — `StaticLinearAnalysis` and
  `SteadyStateThermalAnalysis` both gain an optional `solver:
  LinearSolver | None = None` parameter/field and a `last_solver_result`
  introspection attribute. `None` (the default, and every prior call
  site's implicit value) takes the exact old dense code path unchanged.
  `TransientThermalAnalysis`, `NonlinearAnalysis`, and `DynamicAnalysis`
  are untouched.
- **GUI integration** — the Version 24 GUI's Solver page gains Matrix
  Type / Solver Type selection (Conjugate Gradient offered only when
  Sparse is selected), tolerance/max-iteration controls, and a post-run
  diagnostics panel (DOFs, non-zero entries, density, solve time,
  iterations, residual). Solver logic stays entirely in
  `femtoolkit.application`/`femtoolkit.solvers` — Streamlit contains no
  solver code. Result visualization (Version 22/23) is unchanged
  regardless of which solver produced the result.
- **Four new solver exceptions** — `SolverError`, `SolverConvergenceError`,
  `InvalidSolverConfigurationError`, `UnsupportedSolverError`, extending
  the existing `FiniteElementToolkitError` hierarchy.
- **Documentation** — [`docs/solvers.md`](../solvers.md), covering the
  dense/sparse trade-off, COO/CSR/CSC formats, the solver abstraction, the
  Conjugate Gradient mathematics, convergence criteria, the singular-detection
  fix, and GUI/visualization integration.
- **Example** — `examples/solvers/sparse_solver_comparison.py`, a real
  902-DOF cantilever plate solved three ways with an honest, run-dependent
  performance comparison and an unconditional memory comparison.

## Engineering Impact

- Sparse storage cuts memory for the example cantilever mesh to ~2.8% of
  the equivalent dense matrix (179 KB vs. 6356 KB at 902 DOFs, and the
  ratio improves further as a structured mesh is refined, since non-zero
  density shrinks with `N`).
- No new dependency was required — SciPy has been a core dependency since
  Version 11 (`scipy.sparse.linalg.eigh` for modal analysis); `scipy.sparse`
  and `scipy.sparse.linalg` were already available.
- The architecture does not prevent extending sparse solving to
  `TransientThermalAnalysis`/`DynamicAnalysis` in a future version (a
  sparse mass assembler is already provided), but no such algorithm was
  implemented in this release.

## Verification

- Sparse assembly matches dense assembly exactly (`max abs diff: 0.0`) on
  real Q4/CST mesh contributions, including shared-DOF summation.
- Sparse MPC matches dense MPC exactly.
- All three solvers agree with each other and with the pre-existing dense
  `solve()` to floating-point precision (~1e-15 to 1e-19) on a real
  cantilever mesh and a real thermal plate.
- The singular-system detection fix is verified against a genuine
  under-constrained mechanism (previously returned ~1e10-magnitude
  garbage without raising) and produces no false positive on a correctly
  constrained model (relative residual ~3.86e-14).
- Conjugate Gradient convergence, non-convergence (both raising and
  non-raising modes), and asymmetric-matrix rejection are all verified
  directly.
- `StaticLinearAnalysis`/`SteadyStateThermalAnalysis` integration verified
  end-to-end, including the fully-prescribed (zero-free-DOF) thermal edge
  case.
- The complete regression suite passes: **2328 tests**, including 66 new
  tests added in this release (`test_sparse_assembly.py`,
  `test_solvers.py`, `test_static_linear_solver_integration.py`,
  `test_thermal_solver_integration.py`, plus extensions to the existing
  MPC, application-validation, model-service, and simulation-service test
  files).
- `ruff check .` is clean across the full codebase.
- The GUI Solver → Run → Results workflow was live-verified in a browser
  for Sparse + Conjugate Gradient, matching ad-hoc script numbers exactly
  (66 DOFs, 868 non-zeros, density 0.1993, 32 iterations, residual
  3.371e-05).

## Not Included

New finite elements, new material models, new nonlinear or dynamic
algorithms, a GPU solver, distributed-memory (MPI) solving, cloud
computing, a custom sparse matrix library, automatic mesh adaptation,
topology optimization, CFD, machine learning, or external/commercial
solver coupling. Only one iterative method (Conjugate Gradient) is
implemented, with no preconditioning. See the
[Version 27 preview](../solvers.md#version-27-preview-not-implemented).
