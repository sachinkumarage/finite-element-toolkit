# v36.0.0 — Advanced Surrogate-Assisted Optimization & Adaptive Engineering Design

This release adds `femtoolkit.adaptive`: a small, transparent adaptive-sampling
and refinement loop on top of the Version 35 surrogate/reduced-order-modeling
layer, answering the question Version 35 left to a human -- *where, exactly,
should the next expensive high-fidelity sample be spent?* It also adds a
separate, deliberately lightweight Streamlit quickstart application
(`streamlit_app.py`) so the toolkit can be tried locally and later deployed to
Streamlit Community Cloud, distinct from the existing full engineering GUI.

## Added

- **`femtoolkit.adaptive.sampling`** — `normalized_distance`/
  `design_variable_bounds` (unit-independent design-space distance,
  rescaling each dimension to `[0, 1]` before comparing), `exploration_score`
  (minimum distance to any training sample), `error_score` (a Version 35
  `DomainStatus`-based proxy for expected surrogate error), and
  `rank_candidates`/`SamplingStrategy` (`DISTANCE`/`ERROR`/`OBJECTIVE`/
  `HYBRID` — the hybrid combination is `Score(x) = w_e * E(x) + w_o * O(x)`).
  Candidate ranking reuses `is_better_evaluation`/`feasibility_rank` from
  Version 32/33 directly.
- **`femtoolkit.adaptive.candidates`** — `generate_candidate_pool` (drawn
  directly from `DesignVariable.sample()`, reused unchanged from Version 32)
  and `clip_to_bounds`.
- **`femtoolkit.adaptive.trust_region`** — `TrustRegion`: the ball `||x -
  x_c|| <= Delta` in normalized design space, with `expand()`/`contract()`
  bounded by `min_radius`/`max_radius` — a simple foundation, not a full
  trust-region optimization algorithm.
- **`femtoolkit.adaptive.refinement`** — `RefinementConfig`,
  `SurrogateAcceptanceState` (`SURROGATE_ONLY`/`PENDING_VERIFICATION`/
  `VERIFIED`/`VERIFICATION_FAILED`/`REQUIRES_REFINEMENT`),
  `prediction_agreement` (the `rho` ratio of actual to predicted improvement,
  safe against a near-zero denominator), and `run_refinement_step` — one
  candidate-search-then-verify-then-retrain iteration, built entirely from
  the unmodified Version 35 `verify_against_high_fidelity`/`train_surrogate`
  and `SnapshotDataset.with_additional_snapshots`.
- **`femtoolkit.adaptive.study`** — `generate_initial_samples` (arbitrary
  random design points, executed through the unmodified Version 30
  `Scenario`/Version 34 `evaluate_simulation_batch` path, optionally in
  parallel) and `AdaptiveStudy` — the end-to-end orchestration object:
  initial samples → first surrogate → up to `max_iterations` refinement
  steps, stopping early on `max_high_fidelity_evaluations` or a stalled
  improvement.
- **`femtoolkit.adaptive.results`** — `AdaptiveStudyResult`: keeps
  `best_verified_design`/`best_verified_objective` (from real FEA only)
  strictly separate from `best_surrogate_predicted_design`/
  `best_surrogate_predicted_objective` throughout. A design is reported only
  as "the best verified design found," never as "optimal."
- **New custom exceptions** (`femtoolkit.exceptions`) —
  `AdaptiveOptimizationError` (base), `InvalidTrustRegionConfigurationError`,
  `InsufficientInitialSamplesError`.
- **One new example** (`examples/adaptive/cantilever_surrogate_assisted_optimization.py`)
  — minimizes cantilever beam mass (thickness and width as design variables)
  subject to a maximum-displacement constraint, printing each iteration's
  surrogate prediction next to its high-fidelity verification.
- **A new, separate Streamlit quickstart application** (`streamlit_app.py` +
  `app/streamlit/`) — five pages (Home, FEA Analysis, Optimization,
  Surrogate-Assisted Optimization, Results), distinct from the existing
  full-featured engineering GUI (`femtoolkit.gui`, still reachable via
  `streamlit run src/femtoolkit/gui/app.py`). The core library has zero
  Streamlit dependency; every page only calls existing library APIs, and no
  expensive FEA runs automatically on a bare Streamlit rerun — every run is
  gated behind an explicit button ("Run FEA"/"Run Optimization"/"Run
  Surrogate-Assisted Optimization").
- **Deployment preparation** — a root `requirements.txt` (`.[gui]`,
  installing this package and its `gui` extra from the repository itself —
  no absolute local paths) and a new README section,
  [`## Running the Streamlit Application`](../../README.md#running-the-streamlit-application),
  covering local startup and the basic steps for a future Streamlit
  Community Cloud deployment.
- **Documentation** — [`docs/adaptive.md`](../adaptive.md): the full
  technical guide covering the adaptive loop, candidate generation, all four
  sampling strategies, the trust-region foundation, prediction agreement,
  adaptive refinement, `AdaptiveStudy`, integration with Versions
  30/31/33/34/35, and the Streamlit quickstart app.

## Integration, without silent substitution

- **Version 30/34.** `generate_initial_samples` executes every initial point
  through the unmodified `Scenario`/`apply_scenario` override mechanism and
  `evaluate_simulation_batch` — optionally in parallel via an
  `OrchestrationConfig` — no second parallel-execution system was
  introduced.
- **Version 31.** An `Objective`/`Constraint` built from
  `robust_objective_statistic`/`robust_constraint_statistic` works with
  `AdaptiveStudy` exactly as it already does with Version 33 optimization —
  no UQ system redesign.
- **Version 33.** Candidate ranking reuses `is_better_evaluation`/
  `feasibility_rank` directly; `DesignVariable.sample()`/`.clip()` are reused
  unchanged for candidate generation.
- **Version 35.** Every dataset, scaler, surrogate model, validation metric,
  domain check, and verification record `femtoolkit.adaptive` touches is the
  unmodified Version 35 implementation.

## Limitations

No multi-fidelity modeling, co-kriging, Gaussian processes, deep learning,
neural networks, topology/shape/adjoint optimization, reinforcement
learning, distributed/GPU/cloud execution, digital twins, or formal
reliability methods (FORM/SORM). `rank_candidates` only ever scores a
caller-generated candidate pool — it does not solve a continuous
acquisition-function optimization problem itself, and does not propose new
candidate points on its own the way a true active-learning algorithm would.
`SurrogateEvaluator` is still not wired into a Version 33 population-based
algorithm's own internal search loop — `AdaptiveStudy`'s candidate search is
a separate, simpler mechanism built directly on `rank_candidates`. The
Streamlit quickstart app's surrogate-assisted optimization page drives
`AdaptiveStudy` as a single configured run rather than exposing every one of
`docs/adaptive.md`'s building blocks as its own manual step. See the
[Version 37 preview](../../README.md#roadmap) for what builds on this
foundation next (multi-fidelity modeling and engineering model fusion).
