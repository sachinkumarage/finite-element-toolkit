# v37.0.0 — Advanced Multi-Fidelity Modeling & Engineering Model Fusion

This release adds `femtoolkit.multifidelity`: a small, transparent multi-fidelity
modeling layer that combines a cheap low-fidelity model with the expensive
high-fidelity model by learning and correcting for the low-fidelity model's
systematic error. It answers a different question than Version 36's adaptive
sampling (*where should the next sample go?*): *can a cheap model and the real
model be fused so the cheap model's error is corrected?* Built entirely on the
unmodified Version 30 simulation pipeline and Version 35 surrogate machinery —
no new regression, dataset, or solver logic is duplicated.

## Added

- **`femtoolkit.multifidelity.fidelity`** — `FidelityLevel` (`LOW_FIDELITY`/
  `HIGH_FIDELITY`, each with a relative `estimated_cost`, extensible to
  another level without a complex hierarchy), `FidelityModel` (the ABC),
  `AnalyticalFidelityModel` (a cheap, plain-callable model — no FEA solve),
  `SimulationFidelityModel` (wraps the unmodified Version 30 `Scenario`/
  `apply_scenario`/`SimulationRunManager` — the real solver is reused, never
  duplicated), and `summarize_costs` (a simple cost/accuracy comparison).
- **`femtoolkit.multifidelity.dataset`** — `MultiFidelitySample`/
  `MultiFidelityDataset` (paired and unpaired low-/high-fidelity samples),
  `compute_discrepancy` (`delta(x) = y_H(x) - y_L(x)`, validated for matching
  response names and finite values), `dataset.discrepancies()`, and
  `to_discrepancy_dataset()` — converts every paired sample into a Version 35
  `SnapshotDataset` of `x -> delta(x)`, ready for the unmodified Version 35
  surrogate training pipeline.
- **`femtoolkit.multifidelity.discrepancy`** — `train_discrepancy_surrogate`:
  a thin wrapper around the unmodified Version 35 `train_surrogate`, letting a
  caller select any supported surrogate type
  (`femtoolkit.surrogate.models.SURROGATE_MODEL_TYPES`) for the discrepancy
  model.
- **`femtoolkit.multifidelity.model`** — `FusedPrediction` (keeps
  `low_fidelity_result`, `predicted_discrepancy`, and `fused_prediction` as
  three separate fields, `is_fused_prediction = True`), `MultiFidelityModel`
  (`predict(point)`), `FusionAcceptanceStatus` (`IMPROVED`/`NOT_IMPROVED`/
  `VERIFICATION_FAILED`), and `verify_fused_prediction` — compares the fused
  prediction against a freshly-run real high-fidelity result, reporting
  absolute/relative error for both the raw low-fidelity result and the fused
  prediction.
- **`femtoolkit.multifidelity.validation`** — `FidelityComparisonReport`/
  `compare_fidelity_accuracy`: low-fidelity-only vs. fused-model accuracy,
  computed with the unmodified Version 35 `compute_metrics` (MAE, RMSE, R²,
  relative error), against the same high-fidelity samples.
  `report.improves_on_low_fidelity(response_name)` is never assumed —
  computed and reported honestly.
- **New custom exceptions** (`femtoolkit.exceptions`) — `MultiFidelityError`
  (base), `IncompatibleFidelityResultError`.
- **One new example** (`examples/multifidelity/cantilever_multifidelity_fusion.py`)
  — compares a cheap Euler-Bernoulli beam formula (ignoring shear deformation)
  against the existing continuum FEA cantilever model, trains a discrepancy
  surrogate, and reports whether the fused prediction is actually more
  accurate than the raw analytical formula on held-out thickness values.
- **A new Streamlit page** — **Multi-Fidelity**, extending the existing
  Version 36 quickstart app (`streamlit_app.py`, now six pages) with no new
  Streamlit architecture: configure low-/high-fidelity models, generate
  paired samples, train the discrepancy surrogate, and compare a fused
  prediction against real high-fidelity verification, with every result
  explicitly labeled `LOW-FIDELITY RESULT`, `MULTI-FIDELITY PREDICTION`,
  `HIGH-FIDELITY FEA`, or `VERIFICATION RESULT`.
- **Documentation** — [`docs/multifidelity.md`](../multifidelity.md): the
  full technical guide covering fidelity levels and models, the paired
  dataset, model discrepancy, the discrepancy surrogate, the fused
  prediction, high-fidelity verification, the cantilever example, the
  Streamlit page, and the scope boundary.

## Limitations

No Gaussian processes, co-kriging, deep learning, neural networks, Bayesian
optimization, topology/shape optimization, digital twins, distributed/GPU/cloud
computing, advanced reliability methods, complex multi-fidelity optimization,
or adaptive fidelity selection. Only the simple additive correction
(`y_hat_H(x) = y_L(x) + delta_hat(x)`) is implemented — no multiplicative or
hybrid discrepancy formulations. There is no automatic acceptance criterion for
"the fusion is good enough" — `compare_fidelity_accuracy`/
`verify_fused_prediction` report the numbers; judging whether a fused model is
acceptable for a given engineering use is left to the caller. See the [Version
38 preview](../../README.md#roadmap) for the next planned direction (engineering
digital twin and model updating).
