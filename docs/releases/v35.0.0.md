# v35.0.0 — Advanced Reduced-Order Modeling & Surrogate-Based Engineering Analysis

This release adds a transparent approximation layer on top of the
existing high-fidelity FEA model: reduced-order modeling (Proper
Orthogonal Decomposition) and surrogate-based engineering analysis
(polynomial regression and radial basis function models), so repeated
simulations for design-space exploration, uncertainty quantification,
and optimization can be approximated efficiently — without the
approximation ever silently replacing the real thing. It is a new
package, `femtoolkit.surrogate`, built entirely on top of the existing
Version 30 simulation workflows, Version 31 uncertainty infrastructure,
Version 33 optimization/robust-design infrastructure, and Version 34
parallel execution — no existing module was rewritten.

## Added

- **`femtoolkit.surrogate.datasets`** — `Snapshot`/`SnapshotDataset`:
  an order-preserving, input-output-validated collection of
  high-fidelity evaluations, with `collect_snapshots_from_runs`
  (built from real `SimulationRun` objects), `DatasetSplit`/`split`
  (reproducible train/validation/test partitioning), and
  `with_additional_snapshots` (dataset versioning — `v1 -> v2` — that
  never mutates or loses the identity of a previously trained model's
  dataset).
- **`femtoolkit.surrogate.scaling`** — `Scaler` (`StandardScaler`/
  `MinMaxScaler`), fit on training data only, with `fit_transform`/
  `inverse_transform` so every surrogate prediction returns in
  physical units, never a raw normalized value.
- **`femtoolkit.surrogate.metrics`** — `MetricSet`/`compute_metrics`
  (MAE, RMSE, R², mean/max relative error), with safe handling of
  zero/near-zero denominators.
- **`femtoolkit.surrogate.models`** — the `SurrogateModel` abstraction
  (`fit`/`predict`/`predict_point`/`score`/`validate`/`serialize`/
  `load_state`), and two transparent, interpretable implementations:
  `PolynomialRegressionSurrogate` (degree 1/2, least squares via
  `numpy.linalg.lstsq`) and `RBFSurrogate` (Gaussian/multiquadric
  kernel, data-driven shape parameter, Tikhonov-regularized for
  numerical stability). `predict_point` always returns a
  `SurrogatePrediction` carrying the model/dataset identity, scaling
  configuration, and applicability-domain status alongside the
  predicted value — explicitly labeled, never mistaken for a direct
  FEA result.
- **`femtoolkit.surrogate.validation`** — `SurrogateValidationReport`
  (training/validation/test metrics, cross-validation, engineering
  tolerance checks, warnings), `EngineeringTolerance`
  (caller-defined acceptable error bounds per response), and
  `k_fold_cross_validate`. A surrogate is never evaluated only on its
  own training data, and a good statistical score is never, by itself,
  reported as "safe" — `meets_engineering_tolerances` reflects only
  explicitly configured tolerances.
- **`femtoolkit.surrogate.domain`** — `ApplicabilityDomain`/
  `DomainStatus` (`WITHIN_TRAINING_DOMAIN`/`BOUNDARY`/
  `OUTSIDE_TRAINING_DOMAIN`/`INVALID`), built from raw training inputs
  and checked on every prediction.
- **`femtoolkit.surrogate.rom`** — `PODModel`: Proper Orthogonal
  Decomposition via SVD of a snapshot matrix, with fixed-rank or
  energy-threshold basis selection, `reduce`/`reconstruct`,
  `captured_energy`/`discarded_energy`/`energy_spectrum`. `snapshots.py`
  provides `FieldSnapshot`/`build_snapshot_matrix`/
  `collect_field_snapshots_from_runs` for assembling a full-field
  snapshot matrix from real simulation runs.
- **`femtoolkit.surrogate.workflows`** — `generate_training_dataset`
  (builds a Version 30 parameter sweep and executes it through
  Version 34's `evaluate_simulation_batch`, serial by default or
  parallel on request) and `train_surrogate` (split, fit, and
  validate in one call) in `training.py`; `verify_against_high_fidelity`
  (`AcceptanceStatus`: `ACCEPT`/`REVIEW`/`REJECT`/`FAILED`) in
  `verification.py` — the core "surrogate vs. real FEA" check, run on
  held-out points the model never trained on; `recommend_candidates`
  (`SamplingCandidate`) in `recommendation.py` — an adaptive-sampling
  *foundation* that only ranks a caller-supplied candidate pool and
  never triggers a new simulation on its own; and `Evaluator`/
  `HighFidelityEvaluator`/`SurrogateEvaluator`/`EvaluationBackend` in
  `evaluator.py` — the architecture a future version needs to run
  surrogate-assisted optimization, with every surrogate-derived
  `DesignEvaluation` explicitly marked `metadata["surrogate_derived"] = True`.
- **`femtoolkit.surrogate.persistence`** — safe, explicit
  save/load for surrogate models (plain JSON) and POD models (JSON +
  NumPy `.npz`), never `pickle`; both validate the on-disk schema
  version before trusting a file, raising `ModelPersistenceError`/
  `IncompatibleModelVersionError` rather than silently deserializing
  something unexpected.
- **`femtoolkit.surrogate.report`** — `SurrogateReport` plus
  `render_surrogate_report_markdown`/`_html`/`save_surrogate_report`,
  following the same per-package reporting convention Versions 30-33
  established: Dataset, Surrogate, Reduced-Order Model, Validation,
  Applicability Domain, and High-Fidelity Verification sections.
- **GUI integration** — a new "Surrogate / ROM" workflow page
  (`femtoolkit.gui.workflow_pages.surrogate_page`): a dataset builder
  reusing the Version 30/34 parameter-sweep/execution-mode controls,
  surrogate training (model type, scaling, polynomial degree/RBF
  kernel, split configuration, cross-validation), POD basis fitting
  (fixed rank or energy threshold, with an energy-spectrum chart),
  validation metrics with an interactive engineering-tolerance check,
  an applicability-domain prediction probe, a high-fidelity
  verification panel, and a downloadable Markdown report.
- **New custom exceptions** (`femtoolkit.exceptions`) —
  `SurrogateError` (base), `InsufficientSnapshotsError`,
  `InconsistentSnapshotError`, `InvalidScalingConfigurationError`,
  `SurrogateFittingError`, `InvalidReducedBasisConfigurationError`,
  `ModelPersistenceError`, `IncompatibleModelVersionError`.
- **Five new examples** (`examples/surrogate/`) —
  `benchmark_functions.py` (polynomial/RBF surrogates reproducing the
  analytical `y = x^2`, `y = sin(x)`, and `y = x1^2 + x2^2` functions,
  independent of any FEA simulation); `cantilever_displacement_surrogate.py`
  (a polynomial surrogate for maximum displacement over a
  thickness/modulus grid); `cantilever_stress_surrogate.py` (a stress
  surrogate verified against held-out high-fidelity FEA, demonstrating
  that a good global R² can still fail an engineering tolerance at the
  domain's edge); `pod_cantilever_displacement_field.py` (a POD basis
  built from real nodal-displacement fields across several
  load/thickness cases, with held-out reconstruction error); and
  `surrogate_assisted_optimization.py` (a surrogate-screened candidate
  pool, with the selected candidate accepted only after high-fidelity
  verification).
- **Documentation** — [`docs/surrogate.md`](../surrogate.md): the full
  technical guide covering the high-fidelity model, reduced-order vs.
  surrogate modeling, snapshots/datasets, scaling, the two surrogate
  models, validation, POD, the applicability domain, adaptive
  sampling, integration with Versions 30/31/33/34, high-fidelity
  verification, persistence, reproducibility, and the scope boundary.

## Integration, without silent substitution

- **Version 30/34.** `generate_training_dataset` builds one scenario
  per parameter-sweep combination and executes the whole batch through
  `evaluate_simulation_batch` — no second parallel-execution system was
  introduced.
- **Version 31.** `EvaluationBackend` (`HIGH_FIDELITY`/`SURROGATE`)
  makes explicit, wherever a report is built, whether a Monte Carlo
  study's repeated evaluations came from real FEA or a surrogate —
  `describe_uncertainty_backend` renders this as a one-line, honest
  disclosure.
- **Version 33.** `Evaluator`/`HighFidelityEvaluator`/
  `SurrogateEvaluator` is provided as architecture only in this
  version; the Version 33 optimization algorithms are not yet wired to
  accept one in place of the direct FEA call (see the Version 36
  preview below).

## Testing

- New `tests/surrogate/` package (76 tests): datasets (snapshot
  insertion, dimension validation, serialization, versioning,
  splitting), scaling (standardization, min-max, inverse transforms,
  zero-variance features, reproducibility), both surrogate models
  (fitting, prediction against known functions, metrics), metrics
  (including zero-response edge cases), POD (SVD, rank/energy-threshold
  selection, reconstruction error, a known-rank-1 synthetic
  `X = a*b^T` verification), applicability domain (inside/boundary/
  outside/invalid), validation (train/test separation,
  cross-validation, engineering tolerance checks), persistence
  (round-tripping, corrupted/incompatible file handling), and
  integration tests that run real small FEA simulations through the
  full "parameter space → FEA → snapshot dataset → surrogate →
  verification" pipeline end to end, including a Version 33
  `SurrogateEvaluator` proof that every result is explicitly marked
  surrogate-derived.
- The complete regression suite passes: **3104 tests total** (76 new
  since Version 34's 3028, zero regressions).
- `ruff check .` is clean across the full codebase.
- A session-exit safety net (`tests/conftest.py`) was added after
  discovering that this suite's heavy, cumulative use of
  `concurrent.futures.ProcessPoolExecutor` across thousands of tests
  can occasionally leave a worker/`resource_tracker` helper process in
  a state that hangs CPython's own multiprocessing atexit cleanup well
  after every test has already passed and been reported — a process-
  teardown artifact of this environment, not a correctness issue.
  `pytest_unconfigure` now force-exits with `os._exit` immediately
  after the terminal summary has printed, bypassing the slow/hanging
  cleanup entirely.

## Limitations

No neural networks, deep learning, Gaussian process regression,
Bayesian optimization, advanced active learning, topology/shape
optimization, adjoint methods, distributed/GPU surrogate training, or
formal uncertainty quantification of a surrogate's own prediction
error. `recommend_candidates` only ever ranks a caller-supplied
candidate pool — it never proposes new candidate points itself.
`Evaluator`/`SurrogateEvaluator` is architecture only; no Version 33
optimization algorithm accepts one yet. POD reduces whatever full-field
vector a caller extracts from a completed simulation run — it has no
built-in knowledge of how to extract a nodal displacement field from
every analysis type. See the [Version 36 preview](../../README.md#roadmap)
for the next planned direction (surrogate-assisted optimization and
adaptive engineering design).
